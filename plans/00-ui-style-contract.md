# 拓界前端视觉合同

> 本文件是所有页面的视觉单一事实来源。任何负责前端的 Codex 在写代码前，必须完整阅读本文件、`frontend/src/styles/main.css`、`frontend/src/pages/HomePage.vue` 和 `frontend/src/modules/ability-growth/AbilityGrowthPage.vue`。不要凭文字印象另起一套设计。

## 1. 产品与界面类型

“拓界”是个人成长与决策工作台，不是营销网站。界面类型以 `Operate` 为主，决策结果页可局部使用 `Compare`。页面第一屏应让用户看见当前状态、主要任务和下一步操作，不能使用宣传式 hero、口号、插画或三张等权营销卡。

整体气质：明亮、克制、可信、适合长时间工作。信息密度中等偏高，优先支持扫读、比较、重复操作。

## 2. 现有页面是视觉基准

本地运行后，以以下页面为像素与交互参照：

- `/`：全局工作台、模块入口、个人状态；
- `/ability`：模块页面的页头、目标概览、AI 输入条、工作区、状态标签、图谱、抽屉式详情、分段内容和弹窗；
- `/decision`：当前只有占位入口，模块2开发者需要按本合同替换其内部内容。

优先级从高到低：

1. 本文件中的硬性 token 和布局规则；
2. `frontend/src/styles/main.css` 已实现的公共类和响应式规则；
3. `/ability` 的实际渲染效果；
4. 模块任务书中的业务布局建议。

若发生冲突，不修改既有 token 来迁就单个页面。先复用公共类，再添加有模块前缀的局部样式。

## 3. 颜色与字体

禁止在 Vue 组件、行内样式或模块私有 CSS 中写新的裸色值。统一使用这些语义 token：

```css
:root {
  --bg: #f6f8fb;
  --surface: #ffffff;
  --surface-subtle: #f9fafb;
  --text: #17202a;
  --text-muted: #667085;
  --border: #e4e7ec;
  --brand: #2563eb;
  --brand-strong: #1d4ed8;
  --brand-soft: #eff6ff;
  --accent: #14805e;
  --accent-soft: #eaf8f2;
  --signal: #b7791f;
  --signal-soft: #fff8e5;
  --overlay: rgba(23, 32, 42, 0.38);
  --glass: rgba(255, 255, 255, 0.88);
  --shadow-soft: 0 8px 24px rgba(23, 32, 42, 0.06);
  --shadow-float: 0 18px 50px rgba(23, 32, 42, 0.14);
}
```

语义不可互换：

| 语义 | 用法 |
|---|---|
| `--brand` | 主要操作、选中态、目标、当前路径 |
| `--accent` | 已完成、已掌握、同步成功、低风险 |
| `--signal` | 进行中、需要注意、中风险、假设提醒 |
| `--text-muted` | 未开始、次级说明、禁用态 |
| `--surface` | 主内容面、输入框、工具面板 |
| `--surface-subtle` | 页面内次级分区、空状态、表头 |

高风险或错误默认使用清晰文案、图标和 `--signal`，不要自行增加大面积红色。确需红色时，先在视觉合同中补充语义 token，再使用。

字体只使用：

```css
font-family: 'DM Sans', 'Noto Sans SC', system-ui, sans-serif;
```

正文基准为 `14px / 1.5`。常用字号：页面目标标题 32px，页面区块标题 20px，卡片标题 13-18px，正文 12-14px，辅助信息 9-11px，眉题 12px。移动端页面目标标题 25px，区块标题 18-20px。禁止用超大数字或超大标题填充首屏，禁止随视口连续缩放字体。

## 4. 间距、尺寸和圆角

- 页面内容最大宽度：模块页 `1320px`，首页 `1120px`；
- 桌面端内容左右内边距：`24px`；移动端：`10-12px`；
- 页面纵向区块间距：桌面 `28px`，移动端 `24px`；
- 面板内部常用间距：`8 / 12 / 16 / 24px`；
- 主按钮高度：`42px`；紧凑按钮：`36px`；移动端触控目标不得小于 `40px`，优先 `42-44px`；
- 图标按钮：`42 x 42px`，工具栏紧凑图标按钮 `32 x 32px`；
- 普通圆角：`5-8px`；卡片最大 `8px`；状态胶囊可使用全圆角；
- 只给浮层和少数主摘要面板使用阴影。普通分区依靠边框和留白，不给每个元素加阴影。

禁止 12px 以上的大圆角，禁止卡片嵌套卡片，禁止彩色左边框装饰，禁止装饰性渐变、光球、玻璃卡片和背景插画。玻璃效果只允许用于吸顶页头和 toast。数据驱动的进度环可以使用 `conic-gradient`，图谱画布可以使用低对比度点阵作为坐标辅助；这两项不能扩展为页面装饰。

## 5. 标准模块页骨架

每个正式模块按以下顺序组织。业务不需要的部分可以省略，但不能随意调换主任务层级：

```text
吸顶页头 64px（移动端 58px）
  返回 | 模块图标和名称 | 保存/同步状态 | 页面主操作

页面内容 max-width 1320px
  目标/场景概览面板
  AI 自然语言输入条（若模块需要）
  主工作区（主画布 + 详情侧栏，窄屏单列）
  比较、知识或结构化结果区
  可解释路径、时间线或历史区
```

标准页头复用 `/ability` 的结构和公共类：

```html
<header class="module-header">
  <div class="module-header-inner">
    <RouterLink class="icon-button" aria-label="返回工作台">...</RouterLink>
    <div class="page-title">
      <span class="page-icon">...</span>
      <div><strong>模块名称</strong><small>一句功能定位</small></div>
    </div>
    <div class="sync-state"><span />已保存</div>
    <button class="primary-button compact">...</button>
  </div>
</header>
```

模块可用自己的前缀替换 `module-*`，但视觉值必须一致。移动端隐藏副标题、页头图标和同步文案；主操作变为只显示熟悉图标的方形按钮，并保留 `aria-label` 和 `title`。

## 6. 标准内容构件

### 区块标题

使用左对齐结构：蓝色 `eyebrow` + `h2`，右侧只能放状态汇总或一个次要操作。不要把标题放进独立卡片。

### 概览面板

白色表面、1px 边框、8px 圆角、轻阴影。左侧是当前目标或场景，右侧是最多两个关键指标。指标用于帮助决策，不展示无依据的排名、成功率和伪精确数字。移动端改为上下布局。

### AI 输入

AI 是工作流入口，不是聊天窗口。使用横向操作条：左侧说明、中央输入、右侧主按钮。输出先形成结构化候选项，展示依据或假设，用户确认后才写入业务数据。移动端输入与按钮纵向堆叠，主按钮占满宽度。

### 按钮

- `.primary-button`：每个局部视区最多一个，蓝底白字；
- `.secondary-button`：白底边框，用于重新生成、确认次级动作；
- `.text-button`：取消、轻量操作；
- `.icon-button`：返回、关闭、编辑、缩放、刷新等熟悉操作，使用 `lucide-vue-next` 图标；
- 禁止用带文字的圆角矩形替代已有通用图标；不熟悉的图标必须有 tooltip 或 `title`。

### 状态

状态必须同时提供颜色、文字和必要的图标，不能只靠颜色：

- 完成/掌握/低风险：绿色；
- 进行中/注意/中风险：琥珀色；
- 目标/选中/建议下一步：蓝色；
- 未开始/缺口/禁用：灰色；
- 高风险：优先用“高风险”文字、警告图标和边框表达，禁止整块高饱和背景。

### 卡片、列表和表格

卡片只用于可重复的独立对象、工具入口、弹窗或真正需要边界的工作面板。页面大区块不漂浮成卡片。密集数据优先用带分隔线的列表或表格；不要把每个指标做成一张卡。

表格表头使用 `--surface-subtle`，单元格用细边框或行分隔线。移动端不要把宽表格压缩到不可读，应改为横向滚动、主次字段折叠或逐方案分段。

### 分段选择和标签页

模式切换用 segmented control，视图切换用 tabs。底色为 `--surface-subtle`，选中项为白色或蓝色，圆角 4-6px。手机端允许横向滚动并设置稳定宽度，动态标签不得挤压页面。

### 弹窗与反馈

弹窗最大宽度约 `540px`，8px 圆角，使用 `--overlay` 遮罩和 `--shadow-float`。保存反馈用底部 toast；加载、空数据、错误状态必须占据稳定高度，避免布局跳动。

## 7. 图、流程与比较视图

- 图谱和分支图必须放在有稳定高度的工具面板中，包含图例和缩放/切换控件；
- 节点宽高稳定，文字不能改变画布布局；
- 手机端允许图内横向滚动，不允许页面整体横向溢出；
- 节点较多时提供列表视图或分层视图；
- 路径/时间线在桌面横向展开，手机端可局部横向滚动；
- 比较页先突出“发生了什么变化”，再展示数值区间、风险和假设；
- 所有 AI 或规则结果都要显示依据、来源或假设，不把预测写成事实。

## 8. 响应式合同

统一断点：

- `> 900px`：桌面工作区，可使用主区域 + 282px 左右侧栏或三列阶段；
- `621-900px`：单列工作区，三列内容折叠为单列；
- `<= 620px`：手机布局，页面边距 10-12px，页头 58px，文字和工具栏允许换行；
- 必须实测 `360 x 800` 和 `1280 x 720`。

移动端硬性要求：

1. `document.documentElement.scrollWidth <= window.innerWidth`；
2. 没有文字遮挡、按钮截断或固定元素覆盖内容；
3. 主操作在首屏或当前任务区可见；
4. 图、表、路径只在自身容器内滚动；
5. 任何输入后的动态内容不应让工具栏、按钮尺寸跳动；
6. 核心信息不能依赖 hover。

## 9. CSS 与组件协作规则

- 公共 token 和跨模块原语由集成人维护；模块开发者不得改 token 的值；
- 优先复用 `.eyebrow`、`.icon-button`、`.primary-button`、`.secondary-button`、`.text-button`、`.compact`、`.status-badge`、`.section-heading`、`.state-panel`、`.spinner`、`.toast-message`、`.modal-backdrop`、`.editor-dialog` 和 `.segmented-control`；
- 新增样式必须使用模块前缀，例如 `.decision-*`，避免 `.card`、`.title` 这类全局名称；
- 不复制一份 token 到模块文件；不使用 `!important` 解决所有权问题；
- 除进度角度、图节点坐标等数据驱动值外，不写行内视觉样式；
- 优先 `flex` 和 `grid`，绝对定位只用于画布节点、标记和局部浮层；
- 动画只用于加载、toast 和必要的状态反馈，并支持 `prefers-reduced-motion`。

## 10. 禁止生成的常见偏差

以下任意一项出现都视为未遵守视觉合同：

- 深色或单一蓝紫色大面积背景；
- 渐变、光晕、漂浮球、装饰性网格或无意义玻璃效果；
- 页面顶部营销 hero + 三张功能卡；
- 每个数字一张卡、卡片套卡片、过度阴影；
- 12px 以上大圆角、胶囊按钮泛滥；
- 自绘 SVG 图标或混用其他图标库；
- 页面中心堆放对称卡片而忽视工作流顺序；
- 在组件里硬编码颜色、后端地址或业务 mock；
- 为填空而编造指标、用户评价、成功率或精确预测；
- 只做静态展示，没有加载、错误、空数据和操作反馈。

## 11. Codex 执行顺序

负责页面的 Codex 必须按此顺序工作：

1. 阅读本文件、三个代码基准文件，并查看 `/` 与 `/ability` 的实际页面；
2. 启动现有前端，查看 `/` 和 `/ability` 的桌面与 360px 实际效果；
3. 列出要复用的公共类、要新增的模块类和页面信息层级；
4. 先完成页面骨架，再实现数据状态和交互；
5. 不修改既有视觉 token，除非集成人已书面同意；
6. 用真实业务文案和 service/mock 数据检查最长文本；
7. 实测桌面与手机截图、页面级横向溢出、按钮可用性和控制台错误；
8. 执行 `npm run build`；
9. 在交付说明中列出复用的公共类、新增样式前缀、两个视口的验收结果和已知问题。

## 12. 视觉完成标准

- 与 `/ability` 放在相邻标签页时，看起来属于同一产品；
- 颜色、字体、按钮、页头、圆角、边框和状态语义一致；
- 首屏能回答“我在哪里、当前状态是什么、下一步做什么”；
- 360px 无页面级横向溢出，1280px 不出现无意义的大面积空白或过宽文本；
- 所有交互状态完整，结构化内容在无 AI Key 时仍可演示；
- `npm run build` 通过。
