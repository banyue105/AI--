## 二、最终页面结构

首页从上到下严格按照以下顺序组织：

```text
全局顶部导航：拓界 | 首页 | 能力成长 | 决策沙盒 | 实践验证与复盘 | 职业规划
第一部分：项目介绍 Banner 大图 + 项目定位 + 行动按钮
第二部分：四个模块的简短介绍 + 模块入口
第三部分：四个模块的亮点展示 + 跳到对应模块亮点介绍的按钮
简洁页尾
```

原来的问候、用户头像、当前目标、最近活动退出首页的主要叙事；确有保留价值时收敛成次要的“继续上次操作”入口，不占据 Banner 上方位置。仅调整展示，不删除用户数据或原有模块能力。

顶部导航承担全站模块切换；中部简介入口帮助用户选择模块；下部亮点按钮进入对应模块的亮点介绍区域。三个位置的点击目的必须清晰，不能全部只滚动到首页同一个区块。

## 四、第一部分：项目介绍 Banner 大图

这一部分必须有实际图像资产与清晰的项目介绍，不能只放一块纯色背景或放大旧的个人问候区。

建议使用宽幅、左文右图的构图：文字保持 HTML 可选择和可访问，右侧为与产品有关的高清主视觉，可使用真实页面截图构成的产品展示图，或原创的成长路径主题图片。手机端改为文字在上、图像在下，避免裁切中文与按钮。

主视觉优先呈现“能力图谱、方案对比、证据复盘、岗位方向”四类真实产品内容，让用户一眼理解项目用途。已有 `frontend/src/assets/tuojie-logo.svg` 可用于品牌区域，不能仅放大 Logo 充当 Banner 大图。

推荐文案：

- 项目名称：拓界
- 标题：让成长有路径，让选择有依据
- 介绍：拓界是一款 AI 个人成长与决策工作台，将目标、经验与现实条件转化为可编辑的能力图谱、可比较的决策方案和可追溯的实践复盘，并通过岗位匹配与 JD 分析提供职业方向参考，帮助你看清下一步行动。
- 主按钮「探索四大模块」：滚动到首页模块入口区 `/#home-modules`。
- 次按钮「开始能力成长」：进入 `/ability`。

桌面 Banner 建议高度约 360–440px，以内容可读为准；手机端自适应，不设裁切文字的固定高度。保留首页正文最大宽度 1120px，图像区域可横向铺开，文字和按钮仍与正文对齐。标题和正文沿用项目字号体系，用图像与留白形成重点。

优先复用项目素材或运行截图；没有合适素材时制作原创主视觉，并保存到项目资产目录。使用图像生成能力时按对应技能执行。图像必须实际存在，不引用猜测路径、临时外链或带版权水印素材；关键文字不要烧录进图片。提供合适的替代文本、尺寸占位和加载失败回退，首屏图片优先加载。

延续浅色、清晰、克制的产品气质，避免蓝紫渐变、光球、全屏深色背景、夸张数字和复杂动效。Banner 的说服力来自项目介绍与真实产品内容。

## 六、第三部分：模块出彩内容

区块标题建议为「看看拓界如何帮助你」，区块配置 ID `home-highlights`。四个模块按能力成长、决策沙盒、实践验证与复盘、职业规划的顺序分别做一个图文区块，桌面可交错排版，手机的阅读顺序统一为标题、说明、预览、按钮。每个区块包含一个明确亮点标题、两到三个具体价值点、相关界面预览和一个定位按钮。此处展示能解释产品价值的具体功能，避免重复中部简介。

### 1. 能力成长：把零散经验变成看得见的成长路径

- 展示能力节点、前置关系和掌握状态。
- 展示“个人技能树 + 方向/阶段知识分类”，从目标出发识别缺口，解释建议路径与顺序；自然语言结果由用户确认后再加入。
- 使用真实能力图谱或成长路径截图；使用演示数据时明确标注。
- 按钮：「查看能力图谱与成长路径」。
- 目标：`/ability#ability-highlights`。

### 2. 决策沙盒：先比较条件变化，再做选择

- 将自然语言转为用户可确认的候选条件。
- 比较基准与变更方案的时间、成本、风险及假设。
- 展示版本比较与回溯，明确数值来自规则推演，不代表结果承诺。
- 按钮：「查看方案推演与版本比较」。
- 目标：`/decision#decision-highlights`。

### 3. 实践验证与复盘：让每次实践留下可追溯的依据

- 按验收项查看材料支持、证据不足或矛盾，并能定位原文引用。
- 补交材料后对比历史判断；同口径下比较预期和实际投入。
- 明确目前反馈为参考记录；能力证据写入、决策模块消费反馈尚未完成联调，不宣称全自动闭环。
- 按钮：「查看证据追溯与复盘变化」。
- 目标：`/module3#practice-highlights`。

### 4. 职业规划：连接当前能力与未来职业方向

- 岗位匹配读取当前能力图谱，逐项显示已有匹配与待补齐技能，并支持保存意向方向和城市。
- 岗位筛选按关键词、方向、城市和用工类型缩小范围，用户可设定目标岗位。
- 带入目标岗位 JD 或粘贴文本，生成匹配点、技能缺口与行动建议，并保存报告快照供回看。
- 使用现有模块截图或轻量预览，显著说明岗位、公司和薪资为演示数据；匹配与 JD 分析采用技能词规则，参考匹配度不是录用概率。不把它描述为已经接入真实招聘平台或远程 AI 推荐。
- 按钮：「查看岗位匹配与 JD 分析」。
- 目标：`/module4/match#career-highlights`。
- 保留既有三个子页面与业务流程，本次只增加亮点介绍和导航接入，不扩展职业测评、简历生成或招聘平台后台。

## 七、亮点按钮必须精准落地

四个跨页面亮点 hash 是本次要新增并验证的锚点契约，不是已存在的功能。统一对应关系如下：

| 模块 ID | 默认模块入口 | 亮点介绍目标 |
| --- | --- | --- |

| `decision-sandbox` | `/decision` | `/decision#decision-highlights` |
| `module3` | `/module3` | `/module3#practice-highlights` |

- 在对应模块页面增加简洁的“模块亮点介绍”区域，配置上述稳定 ID，介绍之后提供进入真实功能区的操作。普通模块访问时可保持紧凑或折叠；从亮点链接进入时应自动展开并定位，保留模块以业务操作为主的层级。
- 介绍锚点必须独立于业务数据加载、选中项目和已有推演结果；首次访问、空数据、后端不可用时仍能看到介绍，不白屏或跳到不存在的元素。

- 改造当前总是返回 `{ top: 0 }` 的 `scrollBehavior`，支持 hash、浏览器前进后退的滚动恢复以及普通路由回顶。
- 处理懒加载和 DOM 挂载时机；不要依赖单一固定延时。重复点击同一路由同一锚点也能重新定位。
- 使用 `scroll-margin-top` 或等价机制扣除全局导航与模块工具栏高度，目标标题不能被遮挡。首页 `home-modules`、`home-highlights` 及既有模块内锚点也应使用正确偏移；保留实践页原有验收、证据和反馈定位。尊重 `prefers-reduced-motion`，同时处理现有全局平滑滚动规则。
- 导航后合理管理焦点，键盘和屏幕阅读器用户能识别目标区域。
- 验证从首页点击、复制链接直接打开、带 hash 刷新、返回首页后再次点击均正常。
- 禁止按钮只有文字、使用空链接、仅弹 toast，或所有亮点按钮都只跳到模块顶部。

## 八、数据、样式与变更边界

- 全局导航、模块入口、亮点按钮共用一份有类型的展示配置，集中维护模块标题、简介、亮点文案、锚点与资产路径；模块 ID、业务入口与状态沿用现有 `ModuleManifest` 和 `homeService`，避免三处各写一份或展示配置擅自覆盖业务状态。
- 静态介绍文案与真实业务结果分开。静态文案可以放专门配置文件；动态结果必须经过现有 API service，mock 留在 service/adapter 层，并标明演示来源。
- 当前 `homeService` 的 `/api/v1/home`、离线 fallback 和后端模块清单都已登记四个模块。保留真实 ID、路由与状态，检查接口响应和 fallback 的一致性，不把模块四写回占位入口；若发现旧响应缺项，按现有注册配置修复入口合并，不虚构业务可用性。
- 首页静态介绍、导航和入口不应依赖个人数据请求成功。动态预览失败仅影响自身区块，提供重试或明确空态；不显示虚假的“已同步”。
- `ModuleId` 已包含四个模块，不为此次首页改版另建模块 ID 或职业规划路由，不为静态介绍新增无关接口或数据库迁移。
- 优先复用 `.eyebrow`、`.section-heading`、`.primary-button`、`.secondary-button`、`.text-button`、`.icon-button`、`.status-badge`、`.state-panel`。
- 新样式分别使用 `.home-*`、`.app-nav-*`、`.ability-*`、`.decision-*`、`.practice-*`、`.career-*` 等明确前缀。保持原有 DM Sans / Noto Sans SC、语义颜色、5–8px 圆角及 900px / 620px 断点。移动触控目标优先 44px。
- 允许为全局导航偏移添加明确命名的布局变量，不修改既有色彩 token，不增加第二套 UI 框架。
- 允许修改首页、共享布局、导航、路由、展示配置、必要类型与模块介绍锚点；不重建工程，不重写其他模块的 store、service、计算规则和数据模型。
- 首页亮点预览优先使用优化后的截图或轻量展示组件，不在首页挂载四个完整业务页面。首屏以外图片懒加载，避免额外业务请求和布局跳动；处理预览中的用户资料等非展示信息。
